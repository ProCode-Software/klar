# Klar Compiler

Welcome to the Klar compiler! The `build` package implements everything you think about the Klar compiler: module resolution, dependency resolution, writing files, etc. The core of the compiler, which includes the parser (`internal/lexer` and `internal/parser`), the typechecker (`internal/analysis`), the optimizer (`internal/optimize`), and the code generator (`internal/codegen`), is made of specialized packages like the ones named above. The `build` package connects them together to process Klar files, from the input paths provided on the CLI, to writing .js files to disk.

1. **Module resolution:** The inputs provided on the CLI are found on disk. We also determine if the input is a single-file, module, or package. Manifests and `klar.build` configurations are also parsed during this step.
2. **Dependency compilation:** The package's dependencies are compiled first.
3. **Loading and parsing:** For each detected submodule, it is loaded from cache, or its files are parsed through Klar's [lexer] and [parser]. Parsing creates an abstract syntax tree (AST) for each file, which is used by the compiler to understand the file's syntax.
4. **Analysis:** Modules are sorted by dependency order (in terms of imports). For example, if module `foo` imports `bar`, `bar` is analyzed before `foo`. During analysis, modules are typechecked. During that process, other information about the module is collected.
5. **Optimization:** This begins the _backend_ of the compiler, mainly focused on converting high-level Klar to low-level JavaScript. When building for production, optimizations are run on the Klar code so the produced JavaScript is more efficient. We do eventually want to support more targets, so most optimizations occur on the Klar AST rather than the JavaScript IR (more on that later). The optimizations run by the compiler include inlining, dead code elimination, and constant folding. See [`internal/optimize`](../optimize/README.md) for more info.
6. **Lowering:** High-level Klar code is lowered to JavaScript immediate representation (IR), yet another tree. The JavaScript IR is similar to the final JS produced by the compiler. For example, `when` statements are lowered to JavaScript `if` or `switch` statements.
7. **Code generation (codegen):** The JavaScript IR is written to human-readable `.js` that JavaScript engines execute. See the [`internal/codegen`](../codegen/README.md) package to learn more.
